# Web UI polish — 2026-10-12

## Changes

- Enabled buttons, links and other interactive controls use pointer cursors. Disabled controls retain a not-allowed cursor. Existing button hover styles now apply only while enabled.
- Revoke-session and disable-MFA actions use a red outline/light-red background, with a slightly stronger red hover. Confirm email/enable MFA use the existing terracotta accent. Neutral actions keep subtle border/background hover changes.
- Keyboard users receive consistent visible focus outlines. Reduced-motion preferences shorten animation/transition effects.
- Mobile buttons have a minimum 44px target in both dimensions. Text inputs use 16px text on narrow viewports to improve legibility and avoid focus-triggered mobile zoom.
- Mobile navigation keeps Vault, Generator and Account accessible when the desktop sidebar is hidden. Current pages have a visible selected state and `aria-current`. Mobile lock remains directly accessible.
- Account security buttons stack at narrow widths and return to natural widths on larger screens. Setup/cancel buttons no longer add a left margin that can push a full-width button outside its container.
- Vault statistics use smaller mobile padding, and score/status labels can wrap. Generator heading/icon layout fits narrow screens. Character-option buttons expose their selected state and have a subtle hover.
- Credential cards shrink within their grid. Search has an accessible name and its add button stays readable in the horizontal layout.
- Delete dialogs fit the dynamic viewport and scroll when necessary. Long credential names wrap, and the close button retains its own space. Destructive confirmation stays red.

The extension already had pointer/disabled cursors, focus outlines and reduced-motion support; these changes target the web app. Authentication, vault encryption, session protections and API behavior are unchanged.

## Validation

Run the existing checks after building:

```powershell
npm run lint --workspace=web
npm run build --workspace=web
npm run test:security --workspace=web
```

ESLint, the production build (including TypeScript), and existing production security/browser checks passed.

Browser layout review used isolated public fixture data, with no live database/email calls. Checked phone widths 320px and 375px, tablet layout 768px and desktop 1280px across login, registration, account/profile editing, generator, unlocked vault, credential creation and delete dialog: 32 page/layout views had no page-level horizontal overflow. Visible phone buttons met the 44px minimum in both dimensions. Computed styles confirmed pointer cursors for enabled actions, not-allowed cursors for disabled controls and a changing red background on destructive hover. Screenshots were inspected for narrow account/generator/create/dialog layouts, including an 80-character unbroken credential title. This browser emulation does not replace testing on physical iOS/Android devices.
